# UI

## Interface Type

Umbra is a client-side React UI source package. It provides GUI foundations for consuming applications but has no standalone screen, router, executable, or application runtime of its own.

## Umbra UI Is the Shared Foundation (GUI Projects)

Umbra is the source of truth for shared design tokens, typography, spacing, visual rhythm, reusable primitives, light/dark theme behavior, and structural shells. Consumers import these foundations from `umbra` and `umbra/theme.css` rather than recreating them locally.

## Ownership Boundary (GUI Projects)

Umbra owns presentation and behavior intended to remain consistent across applications. Consumer repositories own their domain screens, navigation content, workflows, state, data integration, and project-specific composition.

Promote a responsibility into Umbra only when it can be expressed through a project-neutral API. Customize application-specific needs through composition, slots, and callbacks rather than by copying an Umbra component into a consumer.

## Themes and Palettes

`src/styles/theme.css` owns the Outfit font faces, semantic light and dark tokens, blue/green/orange/red status colors, Tailwind mappings, and base element styles. Its `@source` directive lets Tailwind 4 scan Umbra's installed TypeScript source.

`ThemeProvider` supports `light` and `dark`, persists the active value to a configurable `localStorage` key (`theme` by default), follows `prefers-color-scheme` when no valid stored value exists, and toggles `.dark` on the document root. Consumer-specific overrides belong in consumer CSS loaded after Umbra's stylesheet.

## Project UI Structure

- `src/components/ui/` contains reusable primitives and small action presets.
- `src/components/` contains compound controls and shared structural shells.
- `AppShell` owns the sidebar provider, inset content frame, sticky header, settings action, theme action, and main content geometry while accepting consumer-controlled sidebar, actions, and content.
- `SettingsDialogShell` and `SettingsTabSection` own shared settings geometry while accepting consumer tabs, handlers, actions, and content.
- `MonthField` and `SearchDropFilter` provide controlled compound inputs with internal popover state.
- `src/index.ts` defines the supported TypeScript API. Consumers import public UI from `umbra`, not internal paths.

## Project Workflows and Patterns

Containers own spacing; individual text elements do not add outer vertical margins. Use the existing component variants and Tailwind scale rather than near-duplicate utility combinations.

Base UI supplies the interaction foundation for most primitives. Preserve keyboard, focus, disabled, invalid, and accessible-name behavior when changing wrappers. `IconButton` requires an accessible label. Inputs and textareas disable browser autocomplete by default but permit consumer overrides.

Interactive behavior must be checked in a consuming application. Important browser-owned state includes the theme's `localStorage` value and the sidebar's `sidebar_state` cookie, controlled/uncontrolled desktop state, separate mobile state, media-query behavior, and keyboard shortcut.

## Project Styling and Exceptions

Umbra's implemented styles are shared infrastructure; consumer-specific overrides remain in consumer repositories. The content canvas is composed with existing semantic tokens, including `bg-muted/40` in `AppShell`, rather than a separate application background token.

Controls use `text-base md:text-sm` where implemented so mobile fields retain 16-pixel text while desktop controls use the compact scale. The shared mobile breakpoint is below 768 pixels; the sidebar changes to a sheet at that boundary.
